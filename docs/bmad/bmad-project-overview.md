## Documentation Architecture

Following BMad's documentation principles, large monolithic documents have been sharded into focused, manageable components:

**Research Documentation:**
- `docs/research/market-overview.md` - Market analysis and opportunity assessment
- `docs/research/target-personas.md` - Mental health-specific user personas
- `docs/research/competitive-analysis.md` - Healthcare competitor landscape

**Requirements Documentation:**
- `docs/requirements/functional-requirements.md` - Clinical feature specifications
- `docs/requirements/non-functional-requirements.md` - Healthcare compliance requirements

**Architecture Documentation:**
- `docs/architecture/system-overview.md` - Healthcare-compliant system design
- `docs/architecture/data-models.md` - Clinical data structures and APIs

**BMad Configuration:**
- `docs/bmad/healthcare-configuration.md` - Healthcare domain BMad setup
- `docs/bmad/bmad-project-overview.md` - This comprehensive project summary
- `.bmadrc.yml` - BMad configuration file with healthcare specialization

### Knowledge Management Benefits
This sharded approach provides:
- **Focused Expertise:** Each document addresses specific healthcare domain concerns
- **Maintenance Efficiency:** Updates can be made to specific areas without affecting others
- **Team Collaboration:** Different team members (clinical, technical, compliance) can own relevant shards
- **Compliance Auditing:** Easier to locate and review specific compliance documentation

## Technology Stack Alignment with BMad

### BMad-Recommended Healthcare Stack
The technology choices align with BMad healthcare recommendations:

**Frontend:** Next.js 14 (BMad: Modern React framework with healthcare performance requirements)
**Backend:** Supabase (BMad: HIPAA-compliant BaaS reducing regulatory overhead)
